分期实施与完整交付范围

按“先具备完整临床业务骨架，再扩展经过验证的AI场景，最后规模复制”的次序实施。参考周期为12个月，前提是接口和数据可获得、院内责任团队到位、选定组件可复用。采购、注册或临床评价所需时间独立排入计划，不能靠压缩试用期消化。

阶段建议时间建设内容退出条件
准备与设计第0—1个月现状调查、设备和接口清单、目标岗位流程、项目目录、合规与风险范围、数据基线、验收设计。责任、范围、接口、来源和基线正式确认；阻塞依赖有明确处理路径。
一期：临床基础与统一数据第2—4个月建设或集成RIS申请预约登记执行、PACS接入归档阅片、人工报告审核、重要结果沟通；建立身份、事件、权限和版本。试点范围内不依赖AI也能完成真实业务全流程；完成关键故障、身份和恢复测试。
二期：原生AI与知识工作流第5—8个月项目标准、规则模板、上下文与观察服务、AI任务及结果评估；上线2—3个经过验证的场景；报告、质量与随访联动。适用性、候选确认、证据、版本、异常与监测闭环全部具备；临床使用获得必要批准。
三期：运营深化与规模复制第9—12个月完善运营、科研、患者服务和多院区协同；扩充场景包；规则及模型改进、容量与迁移能力验收。合同内功能及场景逐项通过验收，培训、运行交接、持续评测和退出机制到位。

不同交付包清楚区分

交付包包括什么何时可称为完成
核心RIS/PACS包M01—M10的合同范围功能，以及M13/M14/M18的基础管理与运维；可复用医院既有能力。业务、数据和岗位整体联测通过，不只是接口通。
AI原生基础包M15/M16、观察和证据服务、人工确认、运行评估及至少一个完整可用场景。不能只交推理API；必须完成默认触发到岗位使用、反馈和安全降级。
随访与患者服务包M11与报告发布、更正、联系人、责任科室的闭环。任务有承接方和处置状态，患者说明可追溯到正式报告。
多院区／区域包M12及相应身份、资质、传输、任务和治理扩展。跨机构场景与断网恢复验收，不以单院演示替代。
科研与教学包M17及独立授权、脱敏、队列复现和数据集治理。真实授权场景走通，不把临床数据库复制作为交付完成。

前90天的工作包

前4周完成现状与接口验证、标准目录和目标状态机；第5—8周打通一条影像检查的完整人工业务链，建立数据版本和影像入口；第9—12周在非临床或获准测试环境接入首个AI任务，验证候选确认、失败退出和标准回写。90天目标是可验证的系统骨架和场景，不是宣称完成全部临床产品或所有注册流程。

切换与迁移

先进行历史数据盘点，区分全量影像迁移、索引统一与按需历史回迁。按院区、设备或亚专科安排切换窗口；每个窗口只保留一个明确的业务权威写入源，避免两套系统并行重复登记。切换前演练接收、报告、重要结果及回退；切换后逐日对账检查数、实例数、报告状态和费用事件。旧系统转为只读或退出须达到预先约定的数据与连续性标准。

验收体系与量化指标

验收由功能、互操作、性能、安全、临床使用、可运营和可退出七部分组成。以下为待执行的验收设计，不是已完成测试结果。所有指标必须明确适用范围、分母、时间起止、测试环境、样本量和排除原因。

指标定义或建议验收方式判定原则
患者与图像一致性约定安全测试集中的身份、影像、报告和任务关联错误数。测试发现重大关联错误不得放行；测试中零发现不代表真实风险绝对为零。
临床记录可追溯签发报告能否还原所用观察、输入清单、模型、规则和人工确认。试点及验收样本要求全部可追溯；缺失来源不能编造补齐。
AI任务覆盖与成功适用任务数／总任务数；有效完成数／适用且触发任务数分别统计。不适用、输入不足、失败、超时分开；不能删失败样本提高成功率。
报告周转至少分别统计采集完成到初稿、到签发，以及重要结果确认到临床接收。使用中位数、P95和未完成病例时长；比较时控制病例构成与工作负荷。
模型与人机表现按用途评价检出、误报、测量、关键报告错误与临床团队表现。目标在独立验证前预设，包含可信区间和亚组；安全为必要条件而非效率交换项。
规则质量适用规则触发、证实、误拦、信息不足及人工覆盖比例。不以触发数量越多越好；异常负担和临床正确性同时评价。
沟通与随访送达、接收、处置、逾期、失联和不再适用状态的完整性。重要结果不能只验“发出消息”；随访分母只纳入已确认适用任务。
可用性与恢复按第18章固定条件压测和故障演练。各故障域分别报告，冷数据和AI失败不能藏在平均值中。
实际效率与体验操作步骤、手工输入、搜索、审阅时间及岗位负担。减少打字不等于减少总劳动；不把草稿采纳率作为临床质量结论。
开放与可退出标准对象、语义、配置、历史版本和引用能否迁出并被独立重建。以实际导出与重建证据验收，不接受只提供接口说明书。

编号／场景关联模块测试输入与操作预期结果验收证据
T01
身份与临时患者		M01/M04两个同名患者及急诊临时身份并行进入。不串片、不串报告；临时身份核实后关联可追溯且可纠正。身份关联记录及跨对象核验。

目录与组合检查		M01/M02一张申请拆成多个执行项目，随后变更其中一项。来源关系、执行与收费映射准确，不重复执行或丢失历史。医嘱—执行—影像关系清单。
T03
申请缺失与错误规则		M02/M15缺少临床信息，且语义检索命中不适用规则。输出信息不足或未覆盖，不伪造推荐；错误候选被适用性规则排除。输入、检索轨迹和最终输出。

多资源预约		M03设备、人员与准备时间发生冲突，临时急诊插入。硬约束不被突破，调整可解释且没有无授权改约。预约资源账及变更原因。
T05
护理与安全核验		M04对比剂相关资料缺失或矛盾。按批准规则进入核查，职责匹配，保留最终放行依据。核对表、责任人与放行记录。
T06
设备工作列表		M05/M06下发任务，发生取消、执行中止与人工补录。设备与RIS标识一致，最终状态可对账，能力不支持时如实显示。设备联测和消息记录。
T07
实际协议与补扫		M05协议被人工调整，质控模型提出补扫提示。实际参数和原因记录完整，模型不能自行启动补扫。执行记录、质量与事件关联。
T08
部分与乱序影像		M06/M16图像乱序到达，尚未满足目标算法输入条件。可安全接收；不提前宣称全检查完整或全图已分析。输入清单版本和任务状态。
T09
重复与UID冲突		M06相同实例重传及同UID不同内容混合输入。重复不重复计量，冲突隔离，不静默覆盖。对象哈希、隔离与对账日志。
T10
持久化与恢复		M06/M07图像接收后切断一个节点并恢复。符合约定持久化和存储承诺，不丢失已确认对象。故障注入、对象核对和承诺记录。
T11
诊断显示		M08多种传输语法、方向、像素间距及多帧测试。定位、显示和测量符合约定误差；不能显示的对象有明确提示。标准测试图、测量与显示验证。
T12
原图与AI切换		M08/M16同时提供已评估与未评估AI候选。随时可查看无标注原图，候选状态和来源清晰。工作站操作录像与状态数据。
T13
纵向关联		M08/M11两次检查协议不同，病灶匹配存在歧义。不强制配对或生成无效变化量，支持人工纠正。测量方法、匹配与可比性记录。
T14
候选与正式结果隔离		M08/M09医生驳回一项测量并修改另一项。原始输出保留，正式观察反映医生决定，引用指向正确版本。候选、评估与观察三方核对。
T15
报告关键错误		M09/M15注入侧别、否定、单位、数值或所见结论冲突。按规则或复核策略处理，不静默改关键事实。规则输入、判断和人工操作。
T16
并发与签发		M09/M10两名人员同时编辑同一报告，另有越权签发请求。版本冲突可见；只有获准角色按流程签发。并发与权限测试结果。
T17
晚到与更正		M06/M09/M11签发后补传影像或返回新AI结果。原报告不被覆盖，必要更正有独立版本及重新分发。更正链、任务和分发回执。
T18
危急值与无人接收		M10通知失败、接收者不在岗或超时未处置。按制度升级，送达、接收、处置分开；人工入口可用。端到端沟通与处置时点。
T19
随访与撤销		M11随访到期、失联，随后报告更正使任务不再适用。保留原因，更新后续任务，避免持续错误提醒。任务生命周期与患者通知记录。
T20
跨院授权		M12/M18外院同名患者、过期授权和无关人员请求。身份核查与权限分别执行，过期及越权请求被拒绝。跨域认证、关联和访问审计。
T21
统计口径		M13/M14取消、重做、跨日检查与旧版绩效规则混合。统计分母、时点与版本可复核，不误计重复工作。原始事件与报表回放。
T22
规则四态与故障		M14/M15分别输入通过、不通过、不足、不适用及执行故障。五类结果正确区分，故障与不足不计入合格。固定测试集和计算记录。
T23
模型适用范围		M16输入未验证人群、设备协议或损坏图像。按批准范围拒绝或转人工，不标记为正常阴性。适用性策略与任务结果。
T24
重试、取消与超时		M16/M18模型回调重复、超时后迟到、任务取消后返回。不产生重复通知和正式记录，过期结果正确归类。任务键、状态变更和副作用账。
T25
全部AI停用		M07/M09/M10/M11/M16断开影像和语言模型服务。原图、已确认结果、人工报告、临床优先级、既有沟通和随访继续。断开演练与岗位验证。
T26
知识与模型更新		M15/M16发布不合格版本，再执行回滚。未获准版本不能转生产；回滚不篡改历史报告和结果。批准、测试、版本和回放记录。
T27
提示注入与数据泄露		M15/M16/M18病历或外部文档含越权指令，尝试读取另一患者。指令不能扩大工具权限，跨患者与敏感外发受阻。安全测试和访问日志。
T28
临床检索与科研导出		M17/M18按相同条件重复查询，并尝试导出候选与敏感字段。查询可复现、状态可区分、导出授权和脱敏可验证。查询版本、数据字典和导出清单。
T29
迁移与退出		M01/M07/M09/M18导出一组含更正报告、观察、分割和评估的病例并重建。像素、引用、版本和来源可恢复，不依赖原厂私有界面。导出包、独立接收端与校验清单。
T30
负载与机房恢复		全平台运行约定峰值负载，并开展断网或灾备演练。在声明条件下满足SLO；不足项明确，不以平均值掩盖长尾。压测、RPO/RTO测量和恢复对账。

投入分成建设成本与持续运营成本

建设成本包括业务软件或组件集成、接口与迁移、存储及网络、诊断终端、AI算力、知识工程、验证与培训。持续成本包括归档增长、备份、模型或软件许可、算力消耗、知识维护、临床复核、运维与合规。开源组件可以减少部分基础开发，不等于企业级系统无许可义务、无集成成本或无临床验证成本。

年度总拥有成本 = 软件与设备年度摊销
               + 运维与支持 + 备份与存储增长
               + 推理资源与模型许可
               + 知识维护与临床验证 + 集成及合规费用

可核实效益 = 可转化的时间价值 + 可归因的流程成本减少
           + 可验证的资源利用改善

净效益 = 可核实效益 - 新增总成本
# 减少的阅片分钟不自动等于现金节省，也不应与新增检查收入重复计入。

团队至少覆盖产品与流程、RIS业务、DICOM与阅片、后端与数据、AI与评测、知识工程、测试、运维安全及临床代表。可以一人承担多个职责，但身份安全、临床规则、影像显示、数据迁移和上线验证不得成为无人负责的空白。医院需为专家复核和规则维护预留实际工作时间。

    clinical-workflow/    # 重要结果、随访与责任任务
    knowledge-rules/      # 术语、规则、证据和模板
    ai-orchestration/     # 适用性、任务、版本及预算
    analytics-audit/      # 指标、查询、审计与运维

  contracts/              # API、事件Schema、FHIR Profile与示例
  scenario-packs/         # 经审核的场景包，不存生产患者数据
  validation/             # 去标识测试、合约、安全与临床验证脚本
  deployment/             # 环境、监控、备份和恢复配置
  docs/                   # 用途、风险、操作、运维、接口与验收资料

目录表示逻辑边界，不要求每个目录各部署一套集群。受控场景包应包含：适用范围、输入清单、模型配置、规则模板、交互流程、异常策略、测试数据要求、评测结果和上线批准。这样复制的是完整临床工作能力，而不只是复制模型名称与提示词。

建议的应用API契约

应用接口示例（自定义，非FHIR标准端点）用途关键约束
POST /api/ai-jobs申请新的AI任务。校验当前用户与患者关系、用途、输入版本；接收幂等键。
GET /api/studies/{id}/observations获取候选与已确认观察。按状态、来源和权限过滤，保留分页与版本。
POST /api/observations/{id}/assessments接受、修改或驳回候选。保存评估主体、原结果、新版本与必要理由。
POST /api/reports/{id}/sign在院内规定流程下签发。服务端校验资质、报告版本、必需审核和高风险未决问题；AI账户无此权限。
POST /api/reports/{id}/amendments创建报告更正或补充。保留原签发版本，重新审核与分发。
POST /api/communications/{id}/acknowledgements确认重要结果接收。确认主体合法；接收不等于完成临床处置。
