01 / 执行摘要

结论先行：保留主线，重写判据与安全架构

这份材料已经越过“罗列几个AI算法”的阶段：它尝试把检查全过程、岗位责任、结构化数据和持续改进放在一起讨论。我的判断是：适合作为科室战略讨论稿，但不能原样变成采购技术规格或临床上线依据。核心问题不是文字不够专业，而是把“深度融入流程”与“业务依赖模型才能存活”混在一起，并低估了异常处理、证据状态和实际验收的工作量。[D]

建议保留

按岗位描述流程变化；影像、结果、规则、反馈可追溯；不以AI采纳率考核医生；分期交付和数据可迁出。

必须修订

原生判据、候选结果与临床结论的分层、AI停机时的保留能力、风险与置信度的关系，以及硬拦截和人工责任边界。

建议实施路径

先做“标准与证据驱动的影像智能工作平台”，连接现有RIS/PACS，以一个检查项目的报告辅助与质控闭环起步，不先重建整套PACS。

修订后的核心主张
AI默认参与已验证且适用的任务，但不成为诊疗不可绕过的单点。医院持有可治理的临床数据与规则；机器提出候选、人完成必要判断；收益靠对照评估证明，安全靠权限、状态和故障演练保证。

本方案不承诺：诊断效率提升某个固定百分比、所有病种自动预读、所有设备实时质控、全自动签发、自动在线学习，或十二周完成全部临床验证。下文的期限、架构和工程目标均是设计建议，不是已实施结果。

04 / 产品定义与边界

我的定义：标准与证据驱动的AI原生影像平台

建议替换原文的定义
AI原生影像平台，是围绕影像检查的临床任务，把版本化临床上下文、可追溯候选结果、人机协同与持续质量评估作为基础能力的一类信息系统。AI在已验证的适用范围内默认参与工作；其输出能被审阅、拒绝、修改和追踪。系统以人机团队的实际收益证明价值，在AI不可用或不适用时仍保持安全的临床流程、既有资料查询和责任连续性。

这里的“AI原生”是本方案的产品与工程定义，不是已经被证明存在统一认证口径的标准等级。不能仅凭算法数量、是否调用大模型、是否微服务化或是否改变八个岗位，就判定系统成熟。

判据要证明什么不接受什么替代证据
任务默认参与适用任务自动触发，覆盖与失败均可观察一个工具栏按钮或演示病例
结果有状态和证据候选、审阅、签发分层；可回到来源只有一段流畅文字或图片截图
效果是人机团队效果与约定基线比较质量、时效、负担单模型AUC或AI采纳率
安全不依赖AI在线停机、超时和不适用时可继续工作让所有业务退回失去提醒和数据的原始状态
更新受治理版本、评估、批准、灰度、回滚可追溯医生改一次，模型马上自学并上线
资产与接口可迁移标准对象+实现约束+导出包+第三方验证“支持FHIR”“可导Excel”的口头承诺

三种产品形态，不必一步做到最重

A · 增强平台（建议起点）

沿用既有归档、阅片与签发入口，增加标准映射、报告质控、证据检索与AI结果管理。前提是接口与用户上下文能稳定联通。

B · 协同工作平台（演进目标）

平台承接部分工作列表、报告准备、结果确认与闭环任务，RIS/PACS保留清晰的权威记录边界。

C · 全栈替代（按条件选择）

仅在旧系统确需替换且迁移、停机演练、设备联调、历史数据和组织资源充分时考虑，不作为“原生”必要条件。

首期明确不做：完整薪酬绩效改制；跨院自动签发；所有设备的实时控制；不受限的患者医学建议；自研所有病种视觉模型；自动生成并发布临床规则。以上事项不能挤占首期证据闭环和安全建设。

06 / 对象、状态与版本

数据模型：把“事实库”拆成可追责的对象

建议采用“临床上下文—证据—候选观察—审阅—正式记录—任务”六个相互关联的对象域。医生接受一条AI结果，代表一次临床审阅判断，不等同于独立研究中的客观真值。后续病理、随访或专家仲裁需作为单独参照记录，注明适用范围与局限。[S09] [S11]

对象必须包含的内容关键约束
Case / 临床上下文机构、身份域、患者映射、就诊、临床问题、可用病史及缺失项临床问题保留原文和来源时间；未知不默认阴性
OrderMapping / 医嘱映射本地项目、标准项目、版本、拆并关系、侧别和协议医嘱与影像检查允许明确的多对多映射；不强行一一对应
StudySnapshot / 检查快照Study/Series/SOP标识、实例清单、收到时间、就绪判定、摘要哈希新增或撤回影像产生新快照；历史运行仍引用旧快照
Evidence / 证据来源类型、对象引用、帧/分割/空间坐标或文本片段、生成时间影像证据可定位；文本事实不能伪造图像坐标
Finding / 观察对象标识、术语/原词、部位侧别、肯定/否定/不确定、状态同一个病灶可有多次观察；候选与临床确认分离
Measurement / 测量名称、数值、单位、测量方法、来源、误差/可比性标记自动换算需规则；测量变化不等于疾病进展
Assessment / 审阅接受、修改、新增、驳回、未评估、无法评估；审阅者与依据临床相关性另列字段；不把未评估归为驳回
ReportVersion / 报告版本结构化内容、文本、证据链接、签发者、签发时间、修订关系签发快照冻结；之后更正产生新版本并关联通知
Task / 临床任务类型、责任人、期限、状态、接收/处置证据、升级路径必须有人承接；消息发送不等于任务完成
RuleVersion / 规则版本适用条件、证据、有效期、严重度、执行方式、测试用例、发布记录有停用和替代关系；临床语义规则不随模型自动更新
ModelRun / 模型运行输入快照、能力范围、模型及配置版本、原输出、状态、错误、耗时保留未执行、不适用、失败、超时；不能静默丢样本
Outcome / 参照结果病理/随访/仲裁来源、日期、标签、可信范围与盲法信息不是简单从最终报告抄一个“真值”；脱离适用范围不可硬匹配

不是一条状态链，而是三条独立状态轴

运行状态

未安排 → 不适用，或排队 → 运行 → 成功 / 部分成功 / 失败 / 超时 / 取消。成功只表示任务完成，不表示正常。

审阅状态

未评估 / 无法评估 / 接受 / 修改 / 驳回 / 新增。对受影响的后续版本需重新审阅，不能继承旧确认。

临床记录状态

草稿 → 待审核 → 已签发 → 补充/更正。来源异常可隔离候选，但不能把已签文书无痕删除。

07 / 标准落地

互操作：不是“支持SR/FHIR”，而是一份可测试的契约

标准承担不同职责，不能把它们写成可随意替代的入库格式。比如FHIR ImagingStudy组织影像检查信息，但本身不保存DICOM实例；DiagnosticReport与Observation之间也有报告和原子结果的边界。[S03] [S04] [S05]

对象/接口建议表达必须另外约定
图像、关键图与分割DICOM对象、SEG；按需要选择呈现对象接收方支持的对象类型、压缩传输语法、坐标和显示行为 [S02] [S08]
测量和可编码征象适用时使用SR TID 1500及相关模板跟踪UID、单位、图像引用、编码、AI与人工版本关系 [S01]
跨系统临床结果FHIR Observation / DiagnosticReport所采用版本、Profile、必填字段、扩展、状态与术语绑定 [S04] [S05]
影像Web访问DICOMweb相关服务认证、查询/检索/存储能力；不把病灶条件检索等同于普通影像索引查询 [S23]
AI推理任务可参照IHE AIW-I / UPS-RS能力目录、任务适用范围、幂等键、取消、超时及错误语义 [S07]
AI结果显示可参照IHE AIR第三方阅片器怎样显示观察、测量、分割和来源 [S08]
AI结果审阅反馈可参照IHE AIRA评估来源、确认状态、临床相关性及版本冲突的本地处理 [S09]
来源和临床待办FHIR Provenance；按集成要求映射Task内部事件仍须包含因果ID、任务责任人、时间和审计 [S06]
旧系统接入保留已验证的HL7 v2/厂商接口适配字段映射、确认机制、异常重发、临床权威记录；不为追求新名词强制全院换FHIR
标准状态必须写清
本次IHE官方索引将AIR、AIW-I和AIRA列于Trial Implementation（试行实施）。它们是可用的工程参考与联调依据，但不应在投标文件中写成对所有供应商已经普遍实现的最终标准。合同应冻结版本、可选项和双方实际支持能力。[S10]

每个接入方交付一张“互操作合同”

合同至少写明：业务用途；对象与字段；术语和单位；标识域；时间语义；版本兼容；数据状态；错误码；重试与去重；授权与用途限制；导出方式；第三方验证用例。对任意临床组合查询，优先通过有授权、可审计的查询服务执行，不要求医生直接连接生产数据库。

标准映射的产品价值：不止同义词

建议把检查项目标准作为贯穿医嘱、协议、模型适用性、报告模板和质控规则的主索引。但名称映射一致不代表扫描内涵相同，更不代表临床上可以直接互认。应同时记录实际序列/扫描范围、造影方式、质量、时间及临床问题；外院资料是否足以支持本次诊疗，保留接诊医师判断。[S21]

对缺失侧别的临床数据，保留unknown或明确的不适用值，不能从词表或默认参数自动推断真实侧别。术语许可、允许部署地区和再分发范围需单独核查，不能默认某个国际词表可以无条件整体迁出。

08 / 正常流程与异常处理

双轨工作流：临床可以继续，AI状态必须可见

临床主线身份与医嘱核对→采集 / 原图可用→医生阅片与报告→审核签发→通知 / 随访任务
AI并行线就绪与适用性判定→限时推理→候选与证据校验→风险路由 / 人工确认→反馈与独立评估

临床主线不以AI完成为前置条件；AI结果一旦有效且未过时，可进入当前审阅工作面。部分模型可以基于特定序列提前运行，但必须标注分析范围，不把“某组图像已收到”解释为“整项检查已完整”。

触发事件系统处理人工与安全边界
StudySnapshotReady按模型能力检查模态、部位、协议、范围和图像质量，再创建幂等任务不适用时显示原因；患者检查和医生阅片继续
AIResultReady校验输入快照、身份、输出模式、单位和证据；生成候选观察重要异常可以优先进入人工复核，但不直接等于正式危急值
EvidenceReviewed只合并已确认且未失效的观察，生成草稿或一致性检查无法评价的内容不能被写成正常；鉴别诊断保留医生判断
ReportSigned持久化签发快照、事实引用、输出版本与任务事件未签报告不能伪装成正式结果对外发布
CriticalFindingConfirmed立即按院内规则发起报告、接收、升级与处置追踪不强制等待整份报告归档；AI退出后任务仍继续
FollowupApproved由授权人员确认对象、到期规则、责任人和通知范围先有责任链，再自动提醒；患者未回复不能直接记为闭环
NewEvidenceAfterSign标记相关观察需重评，生成临床复核任务不能静默改已签报告；更正走受控版本与通知流程

09 / 规则库与RAG

可执行规则：适用性先于推理，证据先于建议

知识服务的核心不是“把文档扔进向量库”，而是把临床要求变为有范围、有版本、有缺失处理的规则包。关系型表与版本化JSON可作为起点；知识图谱只在跨对象关系、规则影响分析和纵向追踪确实需要时引入。

检索不到 / 检索错误：必须有不同路径

1 · 保留原问题

抽取临床问题和约束，保留原文；术语重写不得改变年龄、否定词、侧别和场景。

2 · 检索候选

关键词、编码和向量召回组合；先筛适用范围、证据许可与版本，再谈相似度。

3 · 证据验真

检查引用片段确实存在、支持该命题，及是否与输入和其他规则冲突。

4 · 有界退出

可配置一次同义改写加一次替代检索；仍无合格来源则停止自动建议，列缺失项与人工入口。

不要用模型“自信”补齐知识空白
命中错误规则与完全无命中不是同一种失败。前者应记录“候选被排除的原因”；后者应记录“未覆盖”。两者都不能用生成模型自行捏造指南、检查项目编码或适用条件来填空。

来自病历、网页和上传文档的文字均作为不可信输入。它们不得改变系统权限、工具白名单、检索范围或发布流程。模型输出通过模式校验后也只是候选，不能直接变成数据库写操作或临床指令。

护士/登记缺项与风险来源同屏；一次核对写入后下游复用按授权联系临床/影像医生处理风险；不让护士独自承担诊断性决定
技师已执行协议与必要序列；质量提示附适用范围与原因是否补扫按专业授权与院内流程；记录不必要补扫及追加剂量风险
诊断医生原图、临床问题、历史、候选与草稿联动；未覆盖范围始终可见不能以“看完AI分歧”替代必要的完整阅片；保留一键原图
审核医生关键语义差异、原片证据、需确认清单机器分流不取消既有签发资质与审核要求；低分歧也抽检
临床医生已签报告、关键图、未闭环任务与结果变更通知接收与临床处置分开；外院互认由临床判断
患者已确认内容的通俗说明；部位示意、术语解释和授权复查提示不新增诊断或疗法；示意图标记“非患者原始影像”并审核语义
质控/知识运营随机+风险抽检、规则触发、模型失败和偏移趋势评估不能只看采纳率；规则和数据更正分别流转
排班/管理负荷与资质、团队协作和申诉信息只辅助，不自动决定个人绩效和薪资；二期按需求引入

降低自动化偏误与录入负担

将“原图优先、AI二读”和“AI候选同步显示”等交互方式作为可验证选项，而不是宣称某一种一定最好。所有模式保留系统未分析的部位/病种说明。文句润色自动记录差异；只有侧别、否定、重要数值、诊断含义等语义变化才要求明确原因。对疑难病例支持二读；对正常与人机一致病例保留独立抽检。

人因和人机团队表现应进入评估，而不只测试模型单独的准确率；这与IMDRF GMLP以及DECIDE-AI对临床使用环境和人因的关注方向一致。后者是报告指南，不是认证。[S11] [S13]

11 / 验证、发布、监控

临床与模型治理：持续改进，不等于自动学习

G0 · 用途和风险

确定输入、输出、用户、预期用途、禁用情形、法规与伦理路径。

G1 · 离线验证

独立数据、冻结版本；错误分型、亚组和端到端测试。

G2 · 影子运行

使用真实流量但不影响临床；验证覆盖、失败、延迟和数据偏移。

G3 · 有限临床使用

完成必要审批后，小范围监测人机团队、告警负担与流程收益。

G4 · 扩展部署

达到预设门槛，逐场景扩展；保持回退与事故处置。

G5 · 持续重评

设备、人群、模型、规则变化触发影响评估；重大变更重新过关。

分数、漂移与退出机制

模型原始分数和经过验证的校准概率分开存储。校准需对应模型、任务和人群，不用一个0.8阈值覆盖全部病种；常规分类研究已证明现代神经网络可能存在校准问题，但不能据此断言某个具体医疗模型必然失准。[S12]

输入分布变化是调查信号，不自动等于性能下降。已确认安全问题可按预先批准策略停用受影响模型；单纯统计告警先触发复核。任何停用都将任务转交人工，不自动降低临床安全规则。对设备/协议、人群、病种、失败模式分别监控；低样本亚组显示不确定性，避免用不稳定排名评价医生。

反馈不是自动标注流水线
反馈先进入受控样本池，经质量筛选与授权后用于规则修订、离线训练或再评估。不允许“医生修改 → 直接训练 → 自动替换生产模型”。普通文字偏好、临床更正和客观检测错误应分开建模。

不要把“指标下降”直接写成验收标准。每项指标都应包含起止事件、统计对象、分母、排除项、失败处理、分层、观察窗口与目标来源。以下是建议指标字典；临床目标在基线测量后冻结。

指标可执行口径判定原则
适用覆盖率进入授权自动任务的检查数 / 纳入试点的检查数；另列不适用原因不是越高越好，不能强行扩大注册/验证范围
端到端成功率期限内输出有效且可展示结果的任务数 / 已接受适用任务总数失败、超时不能从分母剔除；阶段耗时单列

急症响应影像达到约定临床可读状态 → 授权医生首次有效处理同时看P50/P95和超时比例；点击页面不必然等于处理

净医生时间辅助前后每例全部操作时间之差，含核查、纠错和告警不得只统计打字时间或草稿生成时间
重要遗漏 / 误报以独立参照标准计算任务相关敏感度、误报及区间事先定义单位为患者/检查/病灶；不可相互替用
无证据内容率已展示/使用草稿中的无支持关键命题数 / 已核查关键命题数区分一般文风和临床重要错误，后者单独监测

数据与资产迁出导出清单、对象数量、哈希、关系重建和第三方导入验证不是交一个压缩包就算完成

工程服务目标示例：只能在负载边界内签约

可将“指定事实查询P95≤2秒”作为待验证工程目标示例，但必须同时锁定数据规模、索引、查询集合、网络、缓存冷热和并发。AI时延按模型与影像体量分别定预算。本报告没有实测这些数值，不建议把它们无条件写进所有医院合同。

对安全不变量采用确定性验收，例如在约定测试集中“无权限签发均被拒绝”“AI关闭不丢失既有任务”“晚到结果不覆盖已签报告”全部通过；这与要求临床模型零错误不是一回事。

原文要求出示一次“真实下线/回滚记录”，建议改为真实记录或受控故障注入演练均可。关键是证明能力，不是证明供应商曾经出过事故。[D]
15 / MVP与阶段关口

实施路线：90天交付一个能验证的闭环

起点建议：选择一个已经有模板、规则与专家资源的检查项目，例如颅脑MRI报告辅助与质控。若已有合规、适用的视觉算法，则接入其结构化结果；若没有，首期仅做临床上下文、医生输入/既有报告的结构化与一致性核查，不冒称具备自动影像预读能力。[D]

MVP范围

单院区、一个检查项目、少量参与医生；一套项目/协议映射、一套版本化规则、一个确认入口、一组异常与回滚用例。

最小业务闭环

检查上下文 → 输入/结果结构化 → 证据候选 → 草稿或质控 → 医生处理 → 冻结与反馈 → 独立复核。

首期排除

全量历史补标、所有病种、绩效薪酬重构、跨院区自动派单和设备实时控制；避免在价值尚未验证前全面替换RIS。

阶段 / 建议时间要完成的工作退出关口
准备 · 第1–2周接口/设备/数据盘点；用途边界；责任人；现状基线；审批路径输入来源和签发权威系统明确；无法满足就不进入临床连接
建模 · 第3–4周对象契约、术语与规则v1；身份映射；用例、审计、超时和降级用合成数据跑通失败与恢复；先过P0架构要求

影子 · 第9–10周在批准范围内接真实流量，不改变临床决策覆盖、成功率、时延和错误模式有可复核记录

二期 · 约3–6个月扩展少量检查项目与算法；报告/危急值/随访任务整合端到端收益和风险均可解释，关键异常测试通过
三期 · 约6–12个月及以后跨院区复制、运营分析、适用设备质控与模型扩展每一新增范围重新确认适用性与能力；持续监控从一期沿用

上述周期是假设接口可获得、医院有人参与且审批顺利时的计划，不是交付承诺。数据规模、样本可用性、采购与伦理周期不足时，应延长阶段，不能压缩安全门槛。

和原有工作衔接，而不是重新铺一套大平台

原文P.21的“单个检查项目—统一规则—模板—内容填充—审核反馈”值得作为最小产品主线。建议进一步将检查项目标准、报告规则、观察模式、AI适用范围和验收样本打成可版本化的场景包。复制到新医院时，重点配置本地术语/协议和工作流，而不是拷贝一套未经验证的阈值。[D]

17 / 投入、价值与采购边界

商业方案：卖可复制闭环，不卖算法数量

我的产品化建议不是先和传统PACS厂商比谁的功能清单更长，而是形成三个可独立交付、逐步组合的业务包。它们共用上下文、事实、规则、反馈与治理，不各自再建一套知识库。

包A · 标准与知识治理

项目/协议/术语映射、规则与模板维护、数据可追溯和可查询。价值来自减少口径不一、维护与集成成本。

包B · 报告辅助与质控

已确认观察的草稿组织、关键语义核查、原片/原文证据、修改与审核反馈。价值靠净时间与错误减少验证。

包C · 任务与质量运营

危急值/随访闭环、模型适用性和运行监控、独立抽检与迭代发布。价值在责任连续性和可治理扩展。

ROI只用可核验的本院输入

年释放工时 = 年检查量 × 实际适用比例 × 每例净节约分钟 ÷ 60
年净收益 = 可兑现的人工 / 外包 / 返工节约 + 经验证的新增服务边际贡献 − 年运行与治理成本

“释放工时”首先是容量与工作负担改善，不自动等于减少工资支出。时间已用于新增业务时，不应再把同一部分时间重复按人工成本计收益。新增服务是否可收费、是否形成收入要另行核实，不把可能的医保支付当既定收入。

成本项必须纳入
一次性投入接口适配、数据清理、历史迁移、临床规则梳理、软件开发、验证测试、安全建设
持续费用模型授权/推理、存储与网络、运维、临床审阅、知识维护、独立评估、培训、停机与备份
容易漏算跨设备联调、误报核查、重复录入、规则升级回归、跨院区本地化、退出迁移成本

合同拆资产，不把所有IP混在一句“归医院”里

建议分清：患者相关记录及医院依法处理的数据；医院定制的配置与流程；供应商既有平台、模型和算法；受许可限制的第三方术语与知识；共同形成的成果。分别约定控制、使用、导出、迁移、更新和许可范围。数据可迁移不等于要求供应商无条件转让模型权重或全部背景代码。

可以分模块计价，但需一名总集成责任方对端到端结果负责。付款关联适用范围内的实际交付与验证证据，不按接入算法个数结算“智能化程度”；临床效果仍不确定的部分，采用试点评估后扩展的决策方式。

可直接替换进原文的8段文字

① 定义 / 替换P.1–2
AI原生PACS或影像平台的关键，不是所有任务都必须等待AI，也不是停用AI后基本功能消失，而是AI在经过验证的适用范围内默认参与任务，输出可追溯、可审阅、可拒绝，人机协同收益可以评估；AI不可用时，核心临床流程、既有记录和已确认任务仍可靠运行。
② 默认预读 / 替换P.2–3
系统根据模态、检查项目、实际协议、图像完整性、人群及模型适用范围决定是否自动分析。不适用、未执行、失败、部分分析和未检出分别呈现。影像医生不因AI排队或失败而被禁止阅片。
③ 候选与事实 / 替换P.7、13
机器观察先作为候选保存，注明来源、版本、分析范围与不确定性。经授权审阅后方可进入相应临床记录。原始候选、临床修改、正式签发和后续参照结果分别保留；任何一层均不得被后一层无痕覆盖。
④ 风险呈现 / 替换P.13、19
系统不以未经校准的单一分数决定所有临床动作。呈现和路由综合考虑任务适用性、数据完整性、错误后果和复核能力。需要关注但证据不足的结果进入人工复核，不直接进入正式诊断或患者通知，也不因分数低而简单丢弃。
⑤ 危急值与随访 / 补充P.3、9
危急值报告流程以经授权确认的临床事件触发，不以报告归档完成为唯一前提。系统分别记录报告、接收、升级、处置及关闭。随访任务经批准后有明确责任人、到期规则及异常处理，在AI服务不可用时继续运行。
⑥ 全程治理 / 替换P.17
监控、审计、适用性判断、异常退出、影子验证和回滚能力在首次临床试用之前建立。后续阶段扩展监测范围与自动化程度，不把基本安全能力留到项目后期。模型或规则升级按影响与风险重新评估。
⑦ 标准与验收 / 替换P.15–16
标准接口要求应明确对象、版本、实施约束、词表、单位、引用、状态及可选能力。通过独立接收系统验证数据与显示的一致性，通过迁出演练验证资产可携带性。支持某一标准名称本身不构成互操作验收通过。
⑧ 成熟度 / 替换P.20–21
成熟度从结果可追溯、任务融入、临床收益、持续治理和安全韧性等方面分别评价。允许一个检查项目先形成完整闭环，再逐步扩展；不要求八个岗位同时改变，也不以是否发生过真实下线事故判定监控能力。
