# 中文文章发布前文风审校

本项目内置 `lieflat-less-ai-tone`：`.agents/skills/lieflat-less-ai-tone/SKILL.md`。来源：[larashero3-dotcom/lieflat-less-ai-tone](https://github.com/larashero3-dotcom/lieflat-less-ai-tone)，按原版 SKILL.md 收录，版权与许可见同目录 `LICENSE`。

## 定位与启用

- 用途：已完成事实、技术和医学审校的中文技术博客、AI Product Builder 文章、官网新闻或产品介绍的**可选**文风清理；不是内容生成、事实核查或医学判断工具。
- Codex/OpenCode 在本项目工作时可从 `.agents/skills/lieflat-less-ai-tone/SKILL.md` 读取规则；无需执行远程 `npx` 安装命令，也不依赖第三方运行脚本。
- 仅当用户要求去 AI 味、润色成稿或明确要求发布前文风审校时启用。不要把它设置成不经审查的自动改写或自动发布步骤。

## 不可改动的内容

- 保留事实、数据、单位、日期、来源、引用链接、引语、证据级别和所有确定性程度（例如「可能」「提示」「建议」「应当」「必须」）。
- 保留医学检查项目与标准编码、影像模态/部位/侧别/序列/检查协议、适应证、禁忌证、患者条件、诊断及治疗判断等专业信息。
- 不改指南/专家共识原文、ACRAC 规则及标准映射数据、临床原始报告、患者个人信息或其他作为证据的原始材料；对患者报告解读的叙述文字须另行经过专业复核。
- 保留 Markdown frontmatter、slug、draft 状态、标题层级、段落和列表/表格结构、代码块、公式、HTML 标签与属性、图片与站内链接；不修改路由、组件、数据文件或源代码。
- 如果某一规则可能改变医学或政策原意，宁可保留原句；不为减少 AI 味而引入新的数据、事实、案例或未经验证的断言。

## 建议流程

1. 作者完成文章，并先核验事实、医学准确性、原始证据和来源。
2. Agent 阅读本地 Skill，只识别其中明确列出的触发项；不凭主观语感扩大改写范围。
3. 默认先提供建议稿和逐项 Diff，每项关联规则编号；**未经确认不覆盖原文**。
4. 检查所有专业保护项无变化后，才把已确认的改动应用到文章草稿。
5. 按 `docs/content-publishing.md` 的既有构建、审查、发布与线上验证流程执行。文风审校通过不代表获得部署/发布授权。

## 可复用提示词

> 请使用 `.agents/skills/lieflat-less-ai-tone/SKILL.md` 审查指定的中文文章。只修改 Skill 明确命中的 AI 文风问题，保留原有事实、医学专业术语、数字、标准编码、适应证与禁忌证、限定词、证据、引用、frontmatter、Markdown/HTML 结构。先列出每项命中的规则编号及建议 Diff，并检查是否有信息丢失或医学含义改变。不要自动覆盖原文、提交、推送或发布；等我确认修改内容。

## 验收检查

- [ ] 每处建议都有 Skill 中对应的规则编号，不超出必要修改范围。
- [ ] 事实、专业术语、数值、时间、证据来源、引用与链接未变。
- [ ] 否定、条件、适用人群、临床风险及确定性程度未变。
- [ ] frontmatter、标题/段落/列表/表格/代码块/HTML 结构未变。
- [ ] 已提供原文与建议稿对比；应用到草稿前经过确认。
- [ ] 发布前运行 `npm run build`；如涉及上线，还须验证 Cloudflare Pages 线上结果。

## 初次效果验证（可选）

建议选 3 篇不同文体的已完成文章（技术研究、标准政策解读、官网新闻），保留 A/B 版本进行盲评。记录：自然程度、专业清晰度、触发规则命中合理性与误改数。**任何事实、医学判断、标准编码、引用或关键限定词错误均为不通过**。未经试用，不将该 Skill 设置为全站强制自动重写。
